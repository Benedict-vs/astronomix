CHEMISTRY WITH ASTRONOMIX: OUR CARBOX VERSION, GRADSOLVE AND THE 16-SPECIES NETWORK
Setup instructions, 17 November 2026 (section 7 added 18 November 2026)
==================================================================================

What you get
------------
One repository that pins everything needed to run our chemistry:

  astronomix (our fork)   the MHD code with the chemistry module
  carbox (our version)    the reaction-network library, with our corrections
  gradsolve               generates the fast per-cell GPU/CPU solver
  the network file        16 species (H, C, O chemistry), 25 rate terms

You do not need a GPU for the first steps. Everything below was tested on a
CPU, in a fresh environment, with Python 3.12 on Linux.


1. Install
----------
  git clone -b feature/multi-gpu-sharding https://github.com/lorenzobranca/astronomix.git
  cd astronomix
  git submodule update --init
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements-chemistry.txt -e . -e external/carbox

The install takes about a minute.

Do NOT clone with "--recurse-submodules". carbox contains a further submodule
(uclchem, not needed here) that is fetched over SSH and fails without a GitHub
SSH key. "git submodule update --init" fetches only what is needed.


2. Run the example
------------------
  python examples/chemistry_cells.py

It takes about 40 seconds on a CPU. It sets up 16 gas cells with densities
from 10 to 10^4 hydrogen nuclei per cm^3 at 100 K, all atomic at the start,
and follows their chemistry for 1 Myr with two solvers:

  - Diffrax Kvaerno5 (the standard implicit solver)
  - a Rosenbrock23 kernel generated by gradsolve (one thread per cell)

What you should see at the end, in both tables:

  n_H = 10 cm^-3      x(H2) = 6.0e-03    T = 19.3 K
  n_H = 10^4 cm^-3    x(H2) = 4.4e-01    T = 15.7 K

and a last line saying the two solvers agree to about 1e-5 dex.
Molecular hydrogen forms faster in the denser cells; that is the physics to
recognise.

Useful options:
  python examples/chemistry_cells.py --no-kernel            Kvaerno5 only
  python examples/chemistry_cells.py --cells 4096 --steps 5
  python examples/chemistry_cells.py --help


3. Run the tests
----------------
  python -m pytest pytests/chemistry/test_warp_stiff_solver.py

Expected: 8 passed, in about a minute.


4. Where things are
-------------------
  external/carbox/data/simple_latent_tgas.csv      the network file
  examples/chemistry_cells.py                      start here; copy and modify it
  astronomix/_modules/_chemistry/_chemistry.py     the chemistry step (update_chemistry)
  astronomix/_modules/_chemistry/_thermochemistry.py   heating and cooling
  astronomix/_modules/_chemistry/_warp_stiff.py    the gradsolve kernel
  astronomix/setup_helpers/chemistry_setup.py      build_chemistry_from_network_file
  README.md, section "Chemistry and the neural chemistry emulator (this fork)"

Each line of the network file is one reaction: two reactants, two products,
three rate parameters, and the mechanism (KA = two-body, CR = cosmic rays,
FUV = photo-reaction, H2Form = H2 formation on dust grains).


5. Parameters used in our simulations
-------------------------------------
  cosmic-ray ionisation rate    3e-17 s^-1
  FUV field                     1e-4
  visual extinction             2 mag
  dust-to-gas ratio             0.01
  solver tolerances             rtol 1e-6, atol 1e-12

The example uses the same values. Keep the FUV field at 1e-4 unless you mean
to change it: this network does not attenuate the H2 photodissociation, and a
field of order one destroys H2 in a few hundred years.


6. On a GPU
-----------
In addition to step 1 (NVIDIA GPU, CUDA 12):

  pip install "jax[cuda12]==0.10.2"

The example script is unchanged. This line has not been tested in a fresh
environment; the versions are those of our working GPU environment.

On a shared GPU machine: one job per GPU, and never a GPU that somebody else
is using. Let autocvd pick a free one for you:

  pip install autocvd
  eval $(autocvd -n 1) python examples/chemistry_cells.py

autocvd waits until a GPU is completely free. Do not use its "--least-used"
option and do not set CUDA_VISIBLE_DEVICES by hand.


7. A network in the KROME format
--------------------------------
astronomix also reads a network written for KROME (for instance
react_galaxy_ism, or our react_galaxy_ism_plus) and evolves it as KROME does:
rate coefficients, photo-reactions from a radiation spectrum, shielding, and
KROME's heating and cooling. carbox is not used for it. The temperature is
always evolved with the abundances.

You need two things that are not in this repository (KROME is GPL-3): the
network file, and the "data" folder of a KROME installation
(https://bitbucket.org/tgrassi/krome). Ask for both.

  python examples/chemistry_krome_network.py \
      --network /path/to/react_galaxy_ism_plus --krome-data /path/to/krome/data \
      --draine 1 --shield-habing-dust --no-metal-table

This evolves 16 cells (n_H from 1 to 1e4 cm^-3) for 1 Myr under the
interstellar radiation field, once with Kvaerno5 and once with the per-cell
gradsolve kernel, and prints both results and their difference (a few 1e-5
dex in the abundances). The first build of the kernel for this network takes
about ten minutes on a CPU; it is cached afterwards. Add "--no-kernel" to
skip it.

  without --no-metal-table    the metals also cool above 1e4 K (KROME's table);
                              only Kvaerno5 runs, the kernel cannot use a table
  --draine X                  radiation field: Draine's times X
  --help                      everything else

Warnings like "wrong format for reaction 36 ... line skipped as in KROME" are
expected with react_galaxy_ism_plus: three lines of that file do not fit their
layout, KROME skips them, and so do we.

Details: README.md, section "Networks in the KROME format" (how to use it in
a simulation, the options of a KROME build and their counterparts here).


8. Things that go wrong
-----------------------
- "network file not found": you skipped "git submodule update --init".
- Use the carbox in external/carbox. Do not install carbox from its main
  branch, and do not use the carbox branch "feature/fused-warp-solver": with
  this network file both give no H2 formation on grains, and main does not
  work with our chemistry module at all.
- The first call of each solver is slow (10 to 20 seconds): the code is being
  compiled. Later calls are fast.
- The chemistry needs double precision. The example switches it on with
  jax.config.update("jax_enable_x64", True); keep that line in your scripts,
  before any other JAX call.
- On a machine without a GPU, a "Warp CUDA error ... no CUDA-capable device"
  message is harmless: the kernel runs on the CPU.
